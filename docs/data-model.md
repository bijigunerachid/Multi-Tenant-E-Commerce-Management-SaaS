# Data model

PostgreSQL with Prisma. This is the design-level overview. The Prisma schema is written
model by model in the phases that need each part (see `roadmap.md`), and every change goes
through `prisma migrate`.

## Conventions

- Primary keys are UUIDs generated by the database.
- Every table has `createdAt`. Mutable tables also have `updatedAt`. Columns are
  `timestamptz` and values are stored in UTC.
- Every **tenant-owned** table has `organizationId` and an index that starts with it.
- Parents that children reference with a composite key declare `@@unique([organizationId, id])`.
- Money is `Decimal(12,2)` with a `currency` `CHAR(3)` (ISO 4217) next to it, or inherited
  from an order or invoice snapshot.
- `onDelete: Restrict` is the default. `Cascade` is allowed only inside one aggregate
  owned by one tenant (for example Order → OrderItem). No foreign key cascades from
  `Organization`.
- Organizations are never hard-deleted by the app. They are suspended, and data removal is
  a documented, audited offboarding job.

## Relationship overview

```
User ─┬─< OrganizationMembership >─ Organization ─┬─< Store ─< InventoryLevel >─ ProductVariant
      │        (role, status)                     ├─< Invitation
      ├─< AuthToken (email verify, reset)         ├─< Category (self-parent)
      └─< AuditLog (actor)                        ├─< Product ─┬─< ProductVariant ─< InventoryLevel
                                                  │            └─< ProductImage
                                                  ├─< Customer ─< Address
                                                  ├─< Order ─┬─< OrderItem ─< InventoryReservation >─ InventoryLevel
                                                  │          └─< OrderStatusHistory
                                                  ├─< InventoryMovement
                                                  ├─< Notification, EmailDelivery
                                                  ├─< AuditLog
                                                  ├── Subscription >─ SubscriptionPlan
                                                  ├─< BillingInvoice
                                                  └── OrganizationCounter (order numbers)
WebhookEvent (platform-level, unique per provider + eventId)
```

## Models

### Identity and tenancy

| Model                      | Key fields                                                                                                                              | Constraints and notes                                                                                                                                                                                                                                                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **User**                   | email, passwordHash, name, emailVerifiedAt, platformRole (`NONE`/`SUPER_ADMIN`), status (`ACTIVE`/`DISABLED`), lastActiveOrganizationId | The app lower-cases emails, and a `CHECK (email = lower(email))` constraint makes the plain unique index case-insensitive in effect. Prisma does not manage expression indexes, so this keeps the constraint visible to Prisma. Not tenant-owned.                                                 |
| **AuthToken**              | userId, purpose (`EMAIL_VERIFY`/`PASSWORD_RESET`), tokenHash, expiresAt, usedAt                                                         | Only the SHA-256 of the token is stored. Single use. Short TTL (reset: 30 min).                                                                                                                                                                                                                   |
| **Organization**           | name, slug, status (`ACTIVE`/`SUSPENDED`), suspendedAt, suspendedReason, defaultCurrency, timezone, contact fields                      | Unique slug.                                                                                                                                                                                                                                                                                      |
| **OrganizationMembership** | userId, organizationId, role, status (`ACTIVE`/`DEACTIVATED`), invitedById                                                              | Unique `(userId, organizationId)`. "At least one active OWNER" is enforced in a transaction that locks the org's owner rows (`SELECT … FOR UPDATE`).                                                                                                                                              |
| **Invitation**             | organizationId, email, pendingEmail, role, tokenHash, expiresAt (7 days), acceptedAt, revokedAt, invitedById                            | Unique `(organizationId, pendingEmail)`: `pendingEmail` equals `email` while pending and is NULL once accepted or revoked (CHECK constraint), so only one invite per email can be pending. Prisma does not manage partial indexes, so this column replaces one. Cannot invite as `OWNER` (CHECK). |
| **OwnershipTransfer**      | organizationId (primary key), fromMembershipId, toMembershipId, expiresAt                                                               | At most one pending transfer per org (the org id is the key); composite FKs keep both memberships in the same org. The row is deleted when accepted, cancelled or expired; the audit log keeps the history.                                                                                       |

### Catalog

| Model              | Key fields                                                                                                                   | Constraints and notes                                                                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Store**          | organizationId, name, slug, currency, timezone, status                                                                       | Unique `(organizationId, slug)`. Onboarding creates the first store. Plan limits cap the number of stores.                                         |
| **Category**       | organizationId, name, slug, parentId                                                                                         | Unique `(organizationId, slug)`. Parent must be in the same org (composite FK).                                                                    |
| **Product**        | organizationId, categoryId, name, description, status (`DRAFT`/`ACTIVE`/`ARCHIVED`), archivedAt                              | Hard delete only when no variant has order items or movements; otherwise the API answers 409 and suggests archiving.                               |
| **ProductVariant** | organizationId, productId, sku, name, options (JSON, e.g. `{size, color}`), price, cost, currency, lowStockThreshold, status | **Unique `(organizationId, sku)`**. `price >= 0`, `cost >= 0`. Every product has at least one variant (the "default" variant for simple products). |
| **ProductImage**   | organizationId, productId, storageKey, mimeType, sizeBytes, position, altText                                                | Max 10 per product. Cascade from Product.                                                                                                          |

### Inventory

| Model                    | Key fields                                                                                                                                                                               | Constraints and notes                                                                                                                                                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **InventoryLevel**       | organizationId, storeId, variantId, onHand, reserved                                                                                                                                     | Unique `(organizationId, storeId, variantId)`; composite FKs to the store and variant of the same org. **CHECK `on_hand >= 0`, `reserved >= 0`, `reserved <= on_hand`.** Available = `onHand - reserved`. Created on the first movement. |
| **InventoryMovement**    | organizationId, inventoryLevelId, type (`RECEIPT`/`ADJUSTMENT`/`RESERVE`/`RELEASE`/`FULFIL`), onHandDelta, reservedDelta, onHandAfter, reservedAfter, reason, note, actorUserId, orderId | Append-only (no update or delete route; DB trigger blocks UPDATE/DELETE). Written in the same transaction as the level change. CHECK: `reason` is set exactly for `ADJUSTMENT`; at least one delta is non-zero.                          |
| **InventoryReservation** | organizationId, orderItemId, inventoryLevelId, quantity, status (`ACTIVE`/`RELEASED`/`CONSUMED`)                                                                                         | Status changes only `ACTIVE → RELEASED` or `ACTIVE → CONSUMED`, guarded by `WHERE status = 'ACTIVE'`, so a double cancel cannot release stock twice.                                                                                     |

Invariant: for every level, `reserved` = the sum of its `ACTIVE` reservations. A
reconciliation test and an admin check verify it.

### Sales

| Model                  | Key fields                                                                                                                                                                                                                                                                   | Constraints and notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Customer**           | organizationId, name, email, phone, notes, archivedAt                                                                                                                                                                                                                        | Unique `(organizationId, email)`; NULL emails do not conflict (walk-in customers). CHECK: email lower-cased, name not blank. Hard delete only until orders reference it (then 409, archive instead).                                                                                                                                                                                                                                                                                  |
| **Address**            | organizationId, customerId, defaultForCustomerId, label, recipientName, line1, line2, city, region, postalCode, country, phone                                                                                                                                               | Composite FK to the customer (cascade within the customer aggregate). `defaultForCustomerId` is unique and equals `customerId` on the default address only (CHECK), so at most one default per customer. `country` is ISO 3166-1 alpha-2 (CHECK).                                                                                                                                                                                                                                     |
| **Order**              | organizationId, storeId, number, customerId, status, currency, subtotal, discountTotal, taxRate, taxTotal, shippingTotal, total, customerName/customerEmail and shippingAddress (snapshots), notes, placedAt, shippedAt, deliveredAt, cancelledAt, cancelReason, createdById | Unique `(organizationId, number)`. `number` is NULL for drafts and assigned when placed, from **OrganizationCounter** (atomic `INSERT … ON CONFLICT DO UPDATE … RETURNING`, starting at 1001; a failed placement rolls back, so no gaps). CHECKs: `total = subtotal - discount_total + tax_total + shipping_total`, amounts ≥ 0, discount ≤ subtotal, 0 ≤ tax rate ≤ 1, drafts have no number or placedAt, cancelled orders have cancelledAt. Totals are computed on the server only. |
| **OrderItem**          | organizationId, orderId, variantId, productName, variantName, sku, unitPrice, quantity, lineTotal, position                                                                                                                                                                  | Snapshot fields are copied when the line is written and never re-read from the catalog. CHECKs: `quantity > 0`, `line_total = unit_price × quantity`. Unique `(orderId, variantId)`. Variant FK is `Restrict` (an ordered product cannot be deleted).                                                                                                                                                                                                                                 |
| **OrderStatusHistory** | organizationId, orderId, fromStatus, toStatus, actorUserId, note                                                                                                                                                                                                             | Append-only (trigger). One row per transition, written in the same transaction.                                                                                                                                                                                                                                                                                                                                                                                                       |

### Platform features

| Model                | Key fields                                                                                                                                                                                   | Constraints and notes                                                                                                          |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Notification**     | organizationId, userId, type, title, body, data (JSON), readAt                                                                                                                               | In-app notifications.                                                                                                          |
| **EmailDelivery**    | organizationId (nullable), toEmail, template, status (`QUEUED`/`SENT`/`FAILED`), attempts, lastError, providerMessageId                                                                      | Email history and retry visibility.                                                                                            |
| **AuditLog**         | organizationId (nullable for platform actions), actorUserId, action, entityType, entityId, metadata (JSON, no secrets), ip, userAgent, requestId                                             | Append-only, enforced by a trigger.                                                                                            |
| **SubscriptionPlan** | code, name, priceMonthly, currency, limits (JSON: maxStores, maxProducts, maxMembers), features, providerPriceId, isActive                                                                   | Unique code.                                                                                                                   |
| **Subscription**     | organizationId, planId, status (`TRIALING`/`ACTIVE`/`PAST_DUE`/`CANCELED`/`EXPIRED`), trialEndsAt, currentPeriodEnd, cancelAtPeriodEnd, provider, providerCustomerId, providerSubscriptionId | One per org. Changed only by verified webhooks or by the trial-expiry job.                                                     |
| **BillingInvoice**   | organizationId, providerInvoiceId, amountDue, amountPaid, currency, status, periodStart, periodEnd, hostedInvoiceUrl                                                                         | Unique `(provider, providerInvoiceId)`. Platform billing only, separate from tenants' own sales.                               |
| **WebhookEvent**     | provider, eventId, type, status (`RECEIVED`/`PROCESSED`/`FAILED`), receivedAt, processedAt, error                                                                                            | **Unique `(provider, eventId)`.** Inserted before processing, so a duplicate delivery is a no-op. No card data is ever stored. |

Sessions are kept in Redis, not in PostgreSQL.
